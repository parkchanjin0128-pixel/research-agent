# 규제 데이터 코딩 기준 — v0.1

기록일/as-of: 2026-10-12. 2회차 시작 시, 규제 행의 intensity 입력 전에 정한 기준이다. 현재 데이터는 **역사적 사건의 부분 구축본**이며 2026-10-12 현행규정 전체를 검증한 데이터가 아니다. Trump 2기 정책과 기준일 현행상태 검증은 5회차로 유보한다.

## 관측 단위와 날짜

- 분류층은 family / subcategory / ECCN이다. `node_id`, `parent_id`로 연결한다. 하나의 ECCN 항목이 여러 하위기술과 연결되면 주 parent 하나와 `related_ids`를 보존하고 중복 집계하지 않는다.
- family·subcategory 행은 ANPRM이 지목한 범위를 뜻한다. 부분 ECCN의 효력일을 부모 전체 효력일로 복사하지 않는다.
- 날짜는 서명/작성일, filing·공개검사일, Federal Register 발행일, 실제 효력일을 구별한다. 발표일은 최초 공개의 증거가 있어야 확정한다.
- `legal control date`는 해당 좁은 품목·성능·소프트웨어 요건의 법적 통제 신설/변경일이다. `China-binding access restriction date`는 그때까지 제한되지 않았던 중국행 거래에 추가 의무·심사강화가 생긴 날이다. 기존 제재기업·최종용도·원산지와 예외를 따로 기록한다.
- 새 품목허가요건은 법적 추가부담이다. 이것만으로 실제 공급중단이나 실현된 수입감소를 관측했다고 쓰지 않는다.
- 시간가변 통제를 단일 최초일로 영구화하지 않는다. 일몰·연장·재분류는 별도 event 행을 추가한다. 미검증 기간은 미확인이다.

## Intensity 사전 판정 규칙

|값|필요한 법적 근거|제외·주의|
|---|---|---|
|0|그 사건 자체는 추가 허가의무·심사제한을 만들지 않음. 의견수렴이면 신호사건의 증분만 0|기존 규제가 없거나 이후에도 미통제라는 의미가 아님|
|1|중국행 해당 거래에 새 허가요건이 있고 case-by-case 또는 승인 가능 심사임을 확인|허가거절·수입중단과 동일시하지 않음|
|2|명시적인 제한적 심사정책이 있으나 일률적인 presumption of denial까지는 아님|단순 NS/RS control reason만으로 2를 부여하지 않음|
|3|presumption of denial 또는 명시적 거래금지|특정 등재기업의 3을 해당 기술 전체로 확장하지 않음|
|미확인|기존 의무, 적용범위, 예외 또는 심사정책 검증 부족|미확인을 0으로 대체하지 않음|

같은 기술도 최종사용자·용도별 강도가 다를 수 있다. 한 칸에는 본 행이 정의한 거래범위의 값만 넣고 예외를 근거 칸에 적는다. family의 최대 강도는 경제적 노출 강도가 아니므로 평균·최대값으로 임의 집계하지 않는다.

## 분류·분모 규칙

ANPRM 원문에 번호가 붙은 기술 예시는 원문 순서대로 행을 만든다. Biotechnology의 (iii) 누락과 `Robot compliers`라는 철자는 원문표기를 보존한다. 괄호 속 예시도 description에 모두 보존한다. `3D printing`은 family 안의 유일한 예시라 별도 예시 행을 만들되, 다른 번호 하위기술과 동일한 법적 단위라고 간주하지 않는다. Faceprint and voiceprint는 한 쌍의 원문 예시로 한 행에 보존한다.

이 분류의 행수는 기술·산업의 경제적 비중이 아니다. 부분통제 비율은 동일 수준의 사전 정의된 분모와 유효한 매핑이 있어야 계산한다. 일단 기술별 최초 접근제한과 후속신호가 검증되기 전에는 ‘미통제 하위기술의 비율’을 발표하지 않는다.
